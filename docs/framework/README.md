# Framework Documentation

## Overview

The framework documentation contains the core methodology, patterns, and best practices for the SpecFirst development approach. This documentation is **technology-agnostic** and focuses on principles, processes, and patterns that can be applied across different technology stacks.

## Core Methodology

The SpecFirst framework follows a **PERA cycle** (Plan-Execute-Report/Review-Adjust) for continuous improvement:

### 🔄 PERA Development Cycle
- **Plan**: Create or refine complete specifications
- **Execute**: Use AI/LLM to generate code from specifications
- **Report/Review**: User reviews generated code and provides feedback
- **Adjust**: Refine specifications based on feedback

### 🔄 Incremental Development
- **Small, focused changes**: 15 minutes to 2 hours per change
- **Phase-based implementation**: Break large features into phases
- **Continuous validation**: Validate each change before proceeding
- **User feedback loops**: Get feedback on each increment

### 🎯 Specification-First Development
- **Start with specifications**: Never implement without complete specifications
- **LLM-regenerable specs**: Ensure specifications can be regenerated by AI
- **User-driven refinement**: Evolve specifications based on user feedback
- **Validation-driven**: Use specifications to validate implementation

### 🤖 AI/LLM-Driven Code Generation
- **AI-powered implementation**: Use AI to generate code from specifications
- **Quality assurance**: TDD ensures generated code meets requirements
- **Iterative refinement**: Improve code through continuous feedback
- **Specification alignment**: Validate generated code against specifications

### 🧪 Test-Driven Development (TDD) as Quality Assurance
- **TDD for Code Generation**: When AI generates code, TDD ensures quality and correctness
- **TDD for Debugging**: When issues arise, TDD helps identify and fix problems
- **TDD for Refinement**: When specifications are refined, TDD validates the changes
- **TDD for Validation**: Tests validate that generated code matches specification requirements

### 📋 Rapid Feedback Integration
- **Early feedback**: Seek feedback at every stage
- **Short feedback loops**: Catch issues early
- **User-driven evolution**: Use feedback to refine specifications
- **Continuous improvement**: Document lessons learned

## Key Principles

### 1. Specification-Driven
- Specifications are the single source of truth
- All implementation must trace back to specifications
- Specifications evolve based on user feedback
- Validation ensures implementation matches specifications

### 2. AI/LLM Integration
- Use AI to generate code from detailed specifications
- AI-generated code must be validated through TDD
- Continuous refinement of both specifications and generated code
- Maintain alignment between specifications and implementation

### 3. PERA Methodology
- **Plan**: Create or refine complete specifications
- **Execute**: Use AI/LLM to generate code from specifications
- **Report/Review**: User reviews generated code and provides feedback
- **Adjust**: Refine specifications based on feedback

### 4. Continuous Validation
- Validate against specifications continuously
- Use automated validation scripts
- Check for regressions after each change
- Maintain specification-implementation alignment

### 5. TDD as Quality Assurance
- Use TDD to validate AI-generated code
- Write tests to ensure code meets specification requirements
- Test both positive and negative scenarios
- Maintain high test coverage for quality assurance

### 6. User-Centric Design
- Design for end-user workflows
- Provide real-time feedback
- Implement graceful error handling
- Test with real users when possible

## Development Workflow

### Phase 1: Specification and Planning
1. **Define requirements** in plain language → `specifications.txt`
2. **Create specifications** with clear acceptance criteria → `SPECIFICATIONS.md`
3. **Plan implementation** phases and milestones → `SPECIFICATIONS.md`
4. **Validate specifications** for completeness and clarity → Ensure LLM-regenerable

### Phase 2: AI Code Generation and TDD
1. **Generate code** using AI from specifications
2. **Write tests** to validate generated code
3. **Test thoroughly** to ensure quality
4. **Refine code** based on test results
5. **Refactor** while keeping tests green
6. **Repeat** for each feature
7. **Document** what changed and why

### Phase 3: User Review and Feedback
1. **Review generated code** against specifications
2. **Test user workflows** end-to-end
3. **Gather feedback** from stakeholders
4. **Document issues** and improvement areas
5. **Plan next iteration** based on feedback

### Phase 4: Specification Refinement and Incremental Development
1. **Refine specifications** based on feedback
2. **Make incremental changes** (15 min - 2 hours each)
3. **Validate each change** before proceeding
4. **Update documentation** at every cycle
5. **Get user feedback** on each increment
6. **Repeat PERA cycle** for continuous improvement

## Common Patterns

### Specification Pattern
```markdown
# Project Name

## Overview
Brief description of the project

## Requirements
- Functional requirements
- Non-functional requirements
- User stories

## Implementation
- Source files
- Documentation files
- Configuration files

## Testing
- Test files
- Test scenarios
- Validation criteria
```

### PERA Cycle Pattern
```javascript
// PLAN: Define specification
const specification = {
    feature: "Calculate total price",
    input: "Array of items with prices",
    output: "Total price as number",
    requirements: ["Handle empty array", "Sum all prices"]
};

// EXECUTE: Generate code using AI
function calculateTotal(items) {
    return items.reduce((sum, item) => sum + (item.price || 0), 0);
}

// REPORT/REVIEW: Validate with TDD
function testCalculateTotal() {
    assert(calculateTotal([]) === 0);
    assert(calculateTotal([{price: 10}, {price: 20}]) === 30);
    assert(calculateTotal([{price: 10}, {price: null}]) === 10);
}

// ADJUST: Refine based on feedback
// If user feedback indicates need for tax calculation:
const refinedSpec = {
    ...specification,
    requirements: [...specification.requirements, "Apply tax rate"]
};
```

### TDD Quality Assurance Pattern
1. **Identify small change** (15 min - 2 hours)
2. **Write test** for specification requirement
3. **Generate code** using AI from specification
4. **Run tests** to validate generated code
5. **Refine code** if tests fail
6. **Validate** against specification requirements
7. **Document change**

## Language-Specific Test Frameworks

### For Beginners (Vibe Coders)
- **JavaScript**: Jest (simple setup, great documentation)
- **Python**: pytest (easy to learn, powerful features)
- **Ruby**: RSpec (readable syntax, good for beginners)
- **Java**: JUnit 5 (industry standard, good IDE support)
- **C#**: xUnit (modern, fast, great .NET integration)
- **Go**: Built-in testing (simple, no dependencies)
- **Rust**: Built-in testing (simple, no dependencies)

### For Intermediate Developers
- **JavaScript**: Vitest (fast, modern, Vite integration)
- **Python**: pytest + pytest-cov (comprehensive testing)
- **Ruby**: RSpec + FactoryBot (advanced features)
- **Java**: JUnit 5 + Mockito (mocking and advanced features)
- **C#**: xUnit + Moq (modern, fast, good tooling)
- **Go**: testify (comprehensive utilities)
- **Rust**: Built-in + proptest (property-based testing)

### For Advanced Teams
- **JavaScript**: Jest + Testing Library (comprehensive ecosystem)
- **Python**: pytest + hypothesis (property-based testing)
- **Ruby**: RSpec + Cucumber (BDD approach)
- **Java**: JUnit 5 + TestContainers (integration testing)
- **C#**: xUnit + FluentAssertions (expressive assertions)
- **Go**: testify + testcontainers (comprehensive testing)
- **Rust**: Built-in + proptest (property-based testing)

### Cross-Platform Testing Tools
- **Playwright**: End-to-end testing for web apps
- **Cypress**: Frontend testing with great UI
- **Selenium**: Cross-browser testing
- **Postman**: API testing
- **Insomnia**: API testing and development

## Best Practices

### Specification Writing
- Use clear, unambiguous language
- Include both functional and non-functional requirements
- Specify success criteria for each requirement
- Make specifications LLM-regenerable
- Include user stories and acceptance criteria

### AI/LLM Code Generation
- Provide detailed, clear specifications
- Use TDD to validate generated code
- Review and refine generated code
- Maintain specification-code alignment
- Document generation decisions

### TDD as Quality Assurance
- Write tests to validate specification requirements
- Test both success and failure cases
- Use descriptive test names
- Keep tests simple and focused
- Maintain high test coverage

### PDCA Cycle Implementation
- Plan thoroughly before generating code
- Do (generate) with clear specifications
- Check (validate) with user feedback and TDD
- Act (refine) based on feedback and test results
- Repeat cycle for continuous improvement

### Documentation
- Keep documentation in sync with implementation
- Use clear, concise language
- Include examples and code snippets
- Update documentation with each change
- Validate documentation completeness
